# AcademicCloud 的学者工作流方向

评估日期：2026-10-06。这是产品方向评估；除 ADR-050 全书 OCR 外，下述建议不构成新功能执行授权。

AcademicCloud 的定位应是以原始资料和可复核证据为中心的研究基础设施。学者要能从一条引用回到具体版本、具体页与原图，区分材料原文、机器识读、人工校订和自己的解释，并在资料更新之后仍能复核过去的判断。

## 竞争产品已经覆盖的能力

WPS 官方提供扫描 PDF OCR、可检索 PDF、批量处理；AI Office 页面也提供摘要、翻译、PDF 问答和可点击页码出处。因此，OCR、摘要、聊天或一个页码链接本身都不足以形成持久差异。官方营销中的准确率或“零幻觉”措辞不是本项目的实测证据。[WPS OCR](https://www.wps.com/feature/pdf-ocr/)、[WPS AI Office](https://www.wps.com/feature/ai-office-suite/)。

Zotero 已将 PDF 批注接到笔记和原文，支持汇集多份资料的批注、附件全文检索与办公软件动态引文。应把它视为研究成果流转的衔接对象。[PDF 阅读与笔记](https://www.zotero.org/support/pdf_reader)、[检索](https://www.zotero.org/support/searching)、[引文插件](https://www.zotero.org/support/word_processor_integration)。

Tropy 重视研究照片、档案来源元数据与转录笔记；Transkribus 重视原图与转录的行级对应、人工校订、阅读顺序和版本。这些产品说明学术 OCR 的价值在后续识读与核对生命周期。[Tropy 文档](https://docs.tropy.org/)、[Transkribus 转录与版本](https://help.transkribus.org/transcribing-manually-0)。

## 已有基础与建议顺序

本项目已经有共享规范资料库与私有研究空间、不可变 sourceId、物理 PDF 页和印刷页/卷/叶定位的区分、阅读位置、高亮、收藏集、页码笔记和多种引文样式。当前页本地 OCR 保存机器原文、独立人工改文和历史，不自动取得规范书目或人工作证的权威。

建议围绕下面的连续工作流发展，而非追求办公功能数量：

1. **识读与校订。** 本次 ADR-050 候选实现逐页保存、暂停续跑、质量问题与带来源导出，尚待部署和真实书籍验收。更长书籍、更大保留额度、无人值守持久队列和独立失败页生命周期需要后续容量与数据决策。印刷页映射仍需人确认。
2. **返回原页的资料检索。** 在选定书籍或收藏集中查人名、地名、术语和原句，显示实际命中文字、上下文、书目、版本与页码。繁简、异体、模糊匹配做成明确选项；OCR 全文索引目前未实现。
3. **可引用证据摘录。** 将引文、页/卷/叶、原图区域、校订状态、版本和个人解释关联起来，材料原文与研究判断分别记录。当前页笔记是基础，完整证据对象尚未实现。
4. **研究问题与异说比较。** 一项问题汇集支持、反证、异说与待核材料，并排查看版本、译本和相关史料。由学者作判断，系统帮助保持依据与差异。
5. **可携带的研究成果。** 导出带出处的摘录、笔记、脚注及结构化数据，补齐 CSL/RIS/BibTeX 等衔接，便于进入 Zotero、WPS/Word 和长期保存。现有私有结构化导出与引文代码是基础；完整互通尚未实现。

例子：研究者考察一项清代制度，在专著、档案与影印史料中找到三处相互矛盾的记载；逐处回看原页并校正 OCR，将它们放入同一研究问题，记录解释；写作时输出三条带版本、页/叶和上下文的证据与脚注。以后补入更清晰的扫描，原证据仍准确指向原来源。这条链的可靠性，是项目最值得积累的专业价值。
