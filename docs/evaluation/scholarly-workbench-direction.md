# AcademicCloud 的学者工作流方向

评估日期：2026-10-06。[ADR-050](../decisions/ADR-050-browser-run-private-book-ocr.md) 全书 OCR 已部署，Mongolia Today 的313页已全部处理，正常下载的TXT和JSONL逐页记录验收通过。第166页低置信度需核对；全书准确率尚未测量。此次新312页的保存时间跨度约108分钟（含暂停），Owner现将提速和离站执行选为后续工作。下述学者工作链仍为产品建议。

AcademicCloud 的定位是以原始资料和可复核证据为中心的研究基础设施。学者从具体版本和页面开始，逐页核对识读文本，积累证据，比较异说，最后形成有出处的论述与引用。原文、机器识读、人工校订和研究者的解释在这条工作链中各有位置。

## 竞争产品已经覆盖的能力

WPS 提供扫描 PDF OCR、可检索 PDF、批量处理，以及摘要、翻译、PDF 问答和可点击页码出处。AcademicCloud 的优先价值应落在原件版本、校订和研究证据之间可持续核对的关系上。[WPS OCR](https://www.wps.com/feature/pdf-ocr/)、[WPS AI Office](https://www.wps.com/feature/ai-office-suite/)。

Zotero 将 PDF 批注接到笔记和原文，支持汇集多份资料的批注、附件全文检索与办公软件动态引文。AcademicCloud 的证据和书目输出应能进入这类成熟的写作流程。[PDF 阅读与笔记](https://www.zotero.org/support/pdf_reader)、[检索](https://www.zotero.org/support/searching)、[引文插件](https://www.zotero.org/support/word_processor_integration)。

Tropy 组织研究照片、档案来源元数据与转录笔记；Transkribus 提供原图与转录的行级对应、人工校订、阅读顺序调整和版本比较。AcademicCloud 应把识读与校订接到共享资料库中的具体原件，再接到每位学者私人的问题、证据和引用。[Tropy 文档](https://docs.tropy.org/)、[Transkribus 转录与版本](https://help.transkribus.org/transcribing-manually-0)。

## 已部署的基础

本项目已有共享规范资料库与私人研究空间、不可变 sourceId、物理 PDF 页与印刷页/卷/叶引用定位的区分、阅读位置、高亮、收藏集、页码笔记和多种引文样式。资料替换后，旧笔记保留原来源关联，并显示来源是否仍可访问。当前页 OCR 保存机器原文、独立人工改文和机器结果历史。

全书 OCR 已部署逐页保存、暂停与手动续跑、质量问题提示和带来源的 TXT/JSONL 导出路径。运行需要阅读器和本人的配对本地设备保持开启；初期限额为单书 500 个物理页、账户合计 500 条保留结果。实际整本与下载验收进度见[验收记录](../evidence/private-book-ocr-20261006.md)。

## 优先工作链与评估方法

| 优先环节 | 已有基础与建议增量 | 可评估的学者任务 |
|---|---|---|
| **1. 原件版本与两套页码** | 已有来源版本和物理页定位；建议建立经人确认的物理页—书内页/卷/叶映射，展示版次与原件可访问状态。 | 输入书内页码能打开正确原页；替换扫描后，旧笔记仍标明原版本，避免引用位置错接到新扫描。 |
| **2. 逐页识读与校订** | 已有机器原文、人工改文、结果历史和全书续跑；建议让待核页清单、原图与转录对照、校订状态形成连续操作。 | 核对一处人名或日期，保存校订后重开仍可比较机器原文；续跑保留已保存结果及其人工改文。 |
| **3. 可引用证据摘录** | 已有高亮与页码笔记；建议将选段、原图区域、原件版本、书内定位、校订状态和个人解释组成独立证据对象。 | 从三份资料各摘一段，每段都能回到可访问的原页，原文与个人解释分别保留。 |
| **4. 研究问题与异说对照** | 收藏集可组织资料；建议按研究问题关联证据，由学者标记支持、反证、异说与待核，并排比较出处与上下文。 | 对同一制度的三种记载建立对照，指出差异来自年代、版本还是作者判断，并给每项判断保留依据。 |
| **5. 可复核引用与开放互通** | 已有引文格式和私人结构化导出；建议输出带版本、页/卷/叶与证据出处的摘录和脚注，并补齐 CSL/RIS/BibTeX 等互通。 | 将选定证据与书目带入 Zotero、WPS/Word，逐条核对引文、版本和页码，并保留可长期读取的结构化副本。 |

上述增量尚待实施；评估应先完成一条真实研究任务。全文检索可在这条链上帮助定位人名、地名和原句，其后续设计应返回实际命中文字、上下文与原页；OCR 全文索引、完整证据对象、研究问题对照和完整互通目前仍属建议。

例如，研究者考察一项清代制度，先在专著、档案与影印史料中定位三处相互矛盾的记载，核对原件和书内页码，再逐处校正 OCR、保存证据与解释，形成异说对照，最后导出脚注。检验这条链时，应逐条检查能否回到对应版本和页面、校订是否保留、原文与解释是否分明、引用能否带入现有写作工具。清晰扫描补入后，旧证据继续保留原来源；复核原页取决于该原件的可访问状态。

## Owner选定的OCR后续工作

本书实际新312页约108分钟（含暂停），逐页保存间隔中位数19.3秒。[ADR-051](../decisions/ADR-051-device-owned-private-book-jobs-and-bounded-warm-ocr.md) 现选定持久私有任务交给本人的连接器执行，并在有界批次内复用已安装模型；关闭网站后任务继续，电脑和连接器仍需运行。设备重启后的正常配对与手动续跑保留服务端断点。该后台改造尚未部署，提速倍数要由实测确定。

建议把可搜索PDF保存为有来源和页覆盖记录的独立本地副本，同时保留原件和TXT/JSONL；已有可用文字层的页面应先复用，避免叠加重复文字。资料库共用OCR则通过明确提交、审校和发布形成机器派生版本，沿用原资料权限。个人笔记、改文、设备与研究活动不隐式公开，线上原件不自动替换。版本错配、漏页错字、图文位置偏移和私人内容混入是发布验收要解决的具体问题。
