# ADR-044 — Private workspace, Collections and Page Notes

Date: 2026-09-15
Status: Accepted; deployed in the September24 combined970 release under the reassessment charter

Implement a small Personal Research Overlay module behind authenticated `/api/workspace` routes. Its dependencies point to authorized Core resource identity; Core file operations never depend on overlay success. It adds no service, paid dependency, AI invocation or original-file rewrite. The user-facing surface is 我的研究, with resource-level access from reading/details and a workspace for returning to saved research.

Reading workflow is an explicit private queued/reading/finished state with independent important and to-cite flags. Do not infer reading progress, duration or current page from opening a native PDF iframe. Collections are named per-account sets of resource IDs; one resource may belong to many sets without changing folders or copying bytes. Collection archival is recoverable and retains its membership.

Page Notes attach to the existing file ID, an ADR-043 immutable source generation and a user-entered one-based physical PDF page. A separate optional citation locator records printed pages, leaves or volumes. The source/page association is immutable; editing note text cannot rebind its evidence to replacement bytes. Only a currently authorized PDF and its exact current source may receive a new note. Existing authored notes remain readable, editable, recoverable and exportable by their author after resource replacement/recycle/access loss; current inaccessible resource metadata and signed URLs are not exposed. Old-source notes remain visibly distinct and never open against new bytes as if the attachment still matched.

Account identity always comes from the authenticated session. Every read, count, write, deletion, restoration, list and export is scoped to that account, with no Owner/Admin exception. Resource authorization is independently re-evaluated before projecting current metadata or adding relationships. Unknown and other-account overlay IDs are indistinguishable. Human-authored edits use revision compare-and-swap; conflicts retain the browser draft. Collection membership uses the collection revision in the same transaction: actual add/remove advances it, a current-revision no-op preserves it, and stale requests conflict even when their requested membership already matches. Notes use recoverable deletion. IDs, account ownership and note attachment cannot change through update routes.

The SQLite overlay migration is additive and independent of the source registry. Foreign keys enforce same-file source associations and same-account collection membership. Reads page before hydration with bounded limits and indexes. Export is an account-scoped, streamed versioned NDJSON document containing authored state and stable attachment IDs, including archived/deleted records, without current inaccessible metadata or object authorization. It is a paged traversal, not a point-in-time database snapshot; each record carries its revision/update time where applicable. No research content, search text or page state enters governance audit or request logs.

UI keeps notes separate from canonical bibliography and preserves the mounted Preview document while opening a research panel. Requests are cancelled/ignored when their resource or account changes. Drafts stay in component memory, not shared local storage; explicit save and unsaved-change protection cover both notes and collection names. Nested history guards protect all affected dialogs before closing any; a prepared document transition consumes the research history entry before opening Preview. History contains opaque dialog IDs, never note text or signed URLs. Cleared reading state remains available for revision checks/export but is filtered before pagination in the active reading list. Lazy loading keeps research controls from enlarging the initial Library bundle unnecessarily.

Verification covers cross-account/Owner non-disclosure, origin/authentication/input validation, stale revisions, source replacement and recycling, recoverable archival/deletion, export isolation, bounded pagination, normal browser create/edit/reopen flows, and responsive keyboard-accessible reading context. Final release uses additive migration recovery and an older-runtime compatibility check with complete migration history. No down-migration or removal of authored research state is a rollback strategy.
