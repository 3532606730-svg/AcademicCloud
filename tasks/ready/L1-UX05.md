# L1-UX05 — Information Architecture and Visual Hierarchy Repair

## Task ID
L1-UX05 — Information Architecture and Visual Hierarchy Repair

## Goal
Make the production-facing shell reflect ADR-022 and remove the current admin-console/engineering-entity feel. The result should be quieter, more polished, and more legible: one shared `资料库`, one clear primary action, restrained controls, concise copy, and administration moved out of the global navigation.

## Scope
Implement the smallest cohesive frontend/product-shell correction after `RF-SHAREDDEFAULT01` establishes the data-flow contract.

### Global shell
- Remove the duplicate top-level `共享资料库` product concept. `资料库` is the canonical shared corpus surface.
- Reduce the top bar to brand/product context, optional global search when already supported, language control, and a compact user menu.
- Remove `管理账户`, `管理公告`, `治理审计`, and `修改密码` from the global top bar.
- Owner user menu exposes `管理后台` and `退出登录`; Member menu stays minimal.

### Owner administration
Provide one coherent administration surface with plain-language sections:
- `成员管理`;
- `投稿审核`;
- `公告`;
- `操作记录`.

`操作记录` is the existing bounded governance/security audit from ADR-015. Do not expand it into research surveillance.

### Library page hierarchy
- Remove the standalone `学术记录` button. `Scholarly Record`/Artifact/Version remain internal domain concepts.
- Where scholarly metadata is useful, surface it naturally through `资料详情`, not an engineering entity browser.
- Keep only one visually strong primary page action: `上传资料`.
- Demote `新建文件夹` to a secondary/icon/overflow action appropriate to shared-corpus governance; ordinary Members must not receive shared-structure mutation authority merely for UI convenience.
- Use restrained borders, spacing, typography, hover/focus states, and action density. Preserve the existing warm/off-white + deep green identity, but remove the cheap “three equal bordered buttons” admin-console look.
- Preserve the already-completed sticky desktop navigation behavior; do not regress it while changing the shell.

### Copy density and descriptive text
- Audit the ordinary user-facing shell, Library, review/admin surfaces, dialogs, empty states, and preview-related UI for descriptive text that does not help the user decide, understand state, recover from an error, or complete an action.
- Remove redundant explanatory prose, repeated labels, and visually noisy small helper text. Do not replace every removed sentence with another description.
- Keep copy that is operationally necessary: status, validation/error recovery, destructive-action consequences, security/access boundaries, accessibility text, and genuinely useful empty-state guidance.
- Prefer concise labels and natural information hierarchy over dense blocks of microcopy.

### Responsive/mobile and preview presentation
- Re-check the mobile/narrow-screen experience rather than merely preserving the current responsive CSS.
- In particular, verify that resource preview presentation, surrounding controls, dialogs/panels, and shell layout remain usable on a narrow viewport and do not look like a desktop composition squeezed into mobile.
- Remove unnecessary surrounding explanatory text or chrome that crowds the mobile preview experience.
- Preserve the accepted preview/download authorization and signed-URL architecture; this is a presentation/interaction repair, not a reopening of the OSS preview architecture.
- Preserve accessibility, keyboard/focus behavior where applicable, and the existing bilingual behavior.

### Stale-state delete bug
Reproduce the visible folder delete failure that reports `该项目状态已变化，请刷新后重试。` on test/synthetic folders.
- Repair stale revision/state refresh or mutation sequencing at the proper API/UI boundary.
- Do not weaken concurrency/CAS protection.
- Do not bypass recycle lifecycle with direct database deletion.
- A conflict should refresh/reconcile the row and permit the user to retry safely; repeated deterministic failure after refresh is a bug.

## Acceptance Criteria
- The normal authenticated shell no longer exposes `共享资料库`, `学术记录`, `治理审计`, or `修改密码` as global navigation/actions.
- `资料库` visibly represents the approved shared corpus from RF-SHAREDDEFAULT01.
- Owner administration is discoverable through the user menu but does not compete with scholarly navigation.
- Library page has a single dominant `上传资料` CTA; secondary actions are visually subordinate and keyboard accessible.
- `Scholarly Record` remains reachable only through normal resource/detail flows where needed by implemented features.
- Governance audit remains Owner-only and is labeled `操作记录` without exposing private research activity.
- User-facing copy has been reviewed across the affected shell/screens; redundant descriptive microcopy and non-actionable small text are removed while necessary state/error/security/accessibility information remains.
- Mobile/narrow-screen Library and preview presentation is directly checked and repaired where needed; preview remains usable without reopening the signed-URL/OSS architecture.
- Completed sticky desktop navigation behavior is not regressed.
- The stale-state folder recycle/delete path succeeds after current-state reconciliation while preserving conflict protection.
- Frontend tests cover Owner vs Member shell, responsive navigation, action hierarchy, admin routes, hidden engineering labels, relevant mobile/preview behavior, and the stale-state recovery path.
- Typecheck/build and focused changed-component tests pass; no unrelated visual-system rewrite is required.

## Visual Direction
Aim for a quiet modern scholarly product: editorial typography for major page titles, clean sans-serif controls/body text, warm neutral background, deep green reserved for brand and primary actions, fewer boxes and borders, more whitespace, concise copy, and low-noise row actions. Do not imitate an enterprise OA/admin dashboard.

## Non-goals
- No full design-system rewrite.
- No new native/mobile app.
- No OCR/full-text search.
- No production data cleanup or permanent deletion.
- No broad metadata implementation beyond the existing detail data required by the shell.
- No redesign of the accepted OSS browser-preview authorization architecture.

## Dependencies
- `RF-SHAREDDEFAULT01` for the corrected canonical Library data-flow semantics.
- `L2-CREDENTIALRESET01` may execute independently for auth behavior, but the final shell must not restore self-service password-change navigation.

## Verification

Include direct narrow-viewport/mobile verification of the affected Library/preview presentation and a focused copy-density review of changed screens. One typecheck/build pass. No production artifact build or historical acceptance replay.
