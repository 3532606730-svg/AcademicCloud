# L1-UX08 — Upload Activity & Source Recovery

## Goal
Turn existing multipart/retry state into a coherent cross-page upload experience and make `选择原文件继续` a true fallback rather than the default resume path.

## Scope

### Global Activity Center
- persistent cross-page upload activity surface, desktop bottom-right and responsive/mobile equivalent;
- immediate feedback after drag/drop or file selection;
- human states for queued, preparing/checksum, reserving, uploading, paused, resumable, completing, verifying, complete and failed;
- file-level progress, uploaded/total bytes, speed and ETA where already available;
- multi-file aggregate state;
- pause/resume/retry/abandon only through existing safe upload contracts;
- completed rows remain briefly visible before quiet dismissal.

### Source Recovery
Use progressive enhancement:

1. same browser session: reuse the existing in-memory `File` automatically;
2. supported browsers: retain a `FileSystemFileHandle` in IndexedDB after an explicit user-granted selection/drag capability where available, then query/request permission and `getFile()` on resume;
3. only when automatic source access is unavailable/denied/stale, show `选择原文件继续`.

Before reusing old multipart parts, revalidate source identity against server-authoritative pending upload identity. Filename/size alone are insufficient; checksum mismatch must fail closed.

## Boundaries
- no upload protocol rewrite;
- no schema migration unless proven unavoidable and separately reviewed;
- no service worker/background-sync requirement;
- no path-string persistence or attempt to bypass browser file permissions;
- unsupported browsers retain current safe manual-source fallback;
- no OSS/provider changes.

## Acceptance
- drag/select shows activity immediately;
- same-session interruption can resume without reopening a file picker;
- supported persisted handle path resumes after reload when browser permission allows;
- permission loss/deleted/moved/changed file produces a clear fallback;
- wrong source file cannot append to prior multipart data;
- Activity Center and `待处理` have distinct roles: live activity vs durable recovery state;
- browser tests cover supported/fallback behavior with capability mocks plus one real-browser journey.
