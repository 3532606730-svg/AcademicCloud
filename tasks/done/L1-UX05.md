# L1-UX05 — Information Architecture and Visual Hierarchy Repair

## Task ID
L1-UX05 — Information Architecture and Visual Hierarchy Repair

## Goal
Make the production-facing shell reflect ADR-022 and remove the current admin-console/engineering-entity feel. The result should be quieter, more polished, and more legible: one shared `资料库`, one clear primary action, restrained controls, and administration moved out of the global navigation.

## Scope
Implement the smallest cohesive frontend/product-shell correction after `RF-SHAREDDEFAULT01` establishes the data-flow contract.

### Global shell
- Remove the duplicate top-level `共享资料库` product concept. `资料库` is the canonical shared corpus surface.
- Reduce the top bar to brand/product context, optional global search when already supported, language control, and a compact user menu.
- Remove `管理账户`, `管理公告`, `治理审计`, and `修改密码` from the global top bar.
- Owner user menu exposes `管理后台` and `退出登录`; Member menu stays minimal.

### Owner administration
Provide one coherent administration surface with plain-language sections:
- `成员管理`;
- `投稿审核`;
- `公告`;
- `操作记录`.

`操作记录` is the existing bounded governance/security audit from ADR-015. Do not expand it into research surveillance.

### Library page hierarchy
- Remove the standalone `学术记录` button. `Scholarly Record`/Artifact/Version remain internal domain concepts.
- Where scholarly metadata is useful, surface it naturally through `资料详情`, not an engineering entity browser.
- Keep only one visually strong primary page action: `上传资料`.
- Demote `新建文件夹` to a secondary/icon/overflow action appropriate to shared-corpus governance; ordinary Members must not receive shared-structure mutation authority merely for UI convenience.
- Use restrained borders, spacing, typography, hover/focus states, and action density. Preserve the existing warm/off-white + deep green identity, but remove the cheap “three equal bordered buttons” admin-console look.
- Preserve responsive/mobile behavior and accessibility.

### Stale-state delete bug
Reproduce the visible folder delete failure that reports `该项目状态已变化，请刷新后重试。` on test/synthetic folders.
- Repair stale revision/state refresh or mutation sequencing at the proper API/UI boundary.
- Do not weaken concurrency/CAS protection.
- Do not bypass recycle lifecycle with direct database deletion.
- A conflict should refresh/reconcile the row and permit the user to retry safely; repeated deterministic failure after refresh is a bug.

## Acceptance Criteria
- The normal authenticated shell no longer exposes `共享资料库`, `学术记录`, `治理审计`, or `修改密码` as global navigation/actions.
- `资料库` visibly represents the approved shared corpus from RF-SHAREDDEFAULT01.
- Owner administration is discoverable through the user menu but does not compete with scholarly navigation.
- Library page has a single dominant `上传资料` CTA; secondary actions are visually subordinate and keyboard accessible.
- `Scholarly Record` remains reachable only through normal resource/detail flows where needed by implemented features.
- Governance audit remains Owner-only and is labeled `操作记录` without exposing private research activity.
- The stale-state folder recycle/delete path succeeds after current-state reconciliation while preserving conflict protection.
- Frontend tests cover Owner vs Member shell, responsive navigation, action hierarchy, admin routes, hidden engineering labels, and the stale-state recovery path.
- Typecheck/build and focused changed-component tests pass; no unrelated visual-system rewrite is required.

## Visual Direction
Aim for a quiet modern scholarly product: editorial typography for major page titles, clean sans-serif controls/body text, warm neutral background, deep green reserved for brand and primary actions, fewer boxes and borders, more whitespace, and low-noise row actions. Do not imitate an enterprise OA/admin dashboard.

- No new native/mobile app.
- No OCR/full-text search.
- No production data cleanup or permanent deletion.
- No broad metadata implementation beyond the existing detail data required by the shell.
