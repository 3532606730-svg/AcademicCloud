## Task ID

L1-E05 — File Management

## Goal

Implement the authenticated, owner-scoped Layer 1 folder and file-management backend over the existing repository and storage boundaries, including a verified pending-upload lifecycle and recoverable deletion.

## Scope

- owner-scoped folder creation, browsing, rename, move, empty-folder soft delete, and restore
- pending upload record creation with a short-lived exact-object upload authorization
- provider metadata verification before file activation
- active folder/file listing and short-lived file download authorization
- file rename and metadata-only move
- file soft delete, recycle-bin listing, restore, and safe permanent deletion
- repository operations and SQLite statements needed by those workflows
- authenticated JSON HTTP routes and stable domain error mapping
- deterministic service, repository, and HTTP tests using in-memory/mock storage only
- file-management API and lifecycle documentation

## Non-goals

- frontend behavior or preview UI
- recursive folder deletion or implicit deletion of contained files
- automatic abandoned-upload cleanup or background workers
- file versioning, sharing, collaboration, search, tags, OCR, RAG, or external-drive connectors
- real OSS credentials, buckets, CORS changes, network requests, or cloud costs
- permanent deletion of active files or non-empty folders

## Acceptance Criteria

- [x] every operation derives `ownerId` from the authenticated server session and ignores no client-supplied ownership field
- [x] folder and file reads/writes cannot cross account boundaries
- [x] names, IDs, MIME types, byte sizes, and JSON bodies are validated with explicit limits
- [x] creating an upload atomically reserves an active name and returns authorization for an opaque exact object key
- [x] an upload becomes active only after provider size, media type, and checksum metadata match the pending record
- [x] listing shows only active direct children of an active folder (or root)
- [x] downloads are authorized only for active owner-scoped files and return short-lived signed URLs
- [x] file/folder rename and move are metadata-only and preserve database uniqueness/cycle constraints
- [x] soft deletion is recoverable; non-empty folder deletion is rejected; recycle listing and restore are owner-scoped
- [x] permanent file deletion requires deleted state, deletes the exact provider object first, and records `purged` only after provider success
- [x] provider failure never marks an object as purged and retry is safe through idempotent deletion
- [x] all drive routes use the existing auth guard and unsafe-request origin protection
- [x] tests, type-checks, builds, dependency audit, migration smoke, and SQLite integrity checks pass
- [x] no frontend, real cloud operation, secret, or Layer 2/3 capability is introduced
