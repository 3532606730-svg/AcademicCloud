## Task ID

L1-E04 — Storage Abstraction

## Goal

Establish a provider-neutral object-storage boundary and a testable Alibaba Cloud OSS adapter for secure browser-direct transfer authorization without using real credentials or cloud resources.

## Scope

- `StorageAdapter` contract owned by the storage module
- cryptographically opaque application-generated object keys independent of display filenames
- short-lived exact-object browser-direct upload authorization with size/type restrictions
- short-lived signed download authorization with safe response filename handling
- provider object metadata lookup required for later upload verification
- idempotent provider object deletion capability required for later permanent deletion
- validated Alibaba Cloud OSS configuration and isolated SDK adapter
- in-memory adapter for deterministic local/integration tests
- contract, adapter, configuration, and failure-isolation tests
- storage contract and provider configuration documentation

## Non-goals

- real OSS accounts, buckets, AccessKeys, CORS changes, costs, or network calls
- upload lifecycle persistence/service/API or browser upload UI
- file listing, download, rename, move, recycle bin, restore, or permanent-delete workflows
- authentication changes
- storage-provider migration or additional production providers
- Layer 2 or Layer 3 features

## Acceptance Criteria

- [x] business/drive modules depend only on `StorageAdapter`, never `ali-oss`
- [x] opaque object keys contain no user-provided filename or trusted path material
- [x] upload authorization is short-lived and restricted to one exact key, content-length range, and media type
- [x] download authorization is short-lived and safely encodes the response filename
- [x] metadata lookup exposes size, provider checksum/ETag, media type, and modification time for later verification
- [x] deletion is exact-key, idempotent at the adapter contract, and never invoked during this task against a real provider
- [x] configuration validates endpoint, bucket, credential presence, duration bounds, and production HTTPS
- [x] the Aliyun SDK is imported only by the Alibaba adapter and its infrastructure wiring
- [x] deterministic tests use fakes/mocks and make no external cloud requests
- [x] tests, type-checks, builds, and dependency audit pass
- [x] no drive business API, frontend feature, cloud resource, or real credential is introduced
