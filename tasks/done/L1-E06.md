## Task ID

L1-E06 — Frontend Interface

## Goal

Deliver a usable, accessible React interface for the completed Layer 1 authentication and file-management API, including direct upload progress and practical file previews.

## Scope

- session recovery, login, logout, and expired-session handling
- responsive folder navigation with active folder/file entries and breadcrumbs
- browser MD5 calculation and direct multipart/form-data upload to authorized object storage with progress
- pending upload visibility, authorization renewal, completion, and actionable failure state
- create folder, rename/move, soft delete, recycle listing, restore, and permanent file delete actions
- short-lived download/open actions and same-session PDF/image/text preview where practical
- accessible loading, empty, error, confirmation, focus, keyboard, and reduced-motion states
- typed API boundary and deterministic frontend tests for critical state/utility behavior
- frontend workflow documentation and visual/browser QA

## Non-goals

- file content editing, sharing, search, tags, versions, collaboration, drag-and-drop hierarchy, batch operations, or recursive folder deletion
- OCR, RAG, semantic features, external connectors, mobile app, or desktop sync
- real OSS credentials/resources or production deployment
- replacing the approved React/Vite architecture or adding a large UI framework

## Acceptance Criteria

- [x] users can log in, recover an existing session, log out, and understand authentication/API failures
- [x] active root/folder contents render responsively with navigation and empty/loading/error states
- [x] upload computes MD5 locally, uses returned POST fields without exposing secrets, reports progress, completes provider verification, and can renew a pending authorization
- [x] create folder, rename/move, soft delete, recycle, restore, and permanent file delete are reachable with confirmations where destructive
- [x] PDF/image/text files can be opened or previewed through short-lived authorized URLs where browsers support them; other types can download
- [x] no owner ID, provider credential, AccessKey secret, or privileged permanent URL is persisted or bundled
- [x] controls are keyboard accessible, labeled, focus-visible, responsive at 320 px, and respect reduced motion
- [x] frontend tests cover API errors, MD5 calculation, navigation/upload state, and critical actions without real network/cloud calls
- [x] repository tests, type-checks, production builds, audit, browser flow, and visual QA pass
- [x] no backend scope expansion beyond small compatibility fixes, cloud operation, or Layer 2/3 capability is introduced
