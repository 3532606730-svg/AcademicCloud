## Task ID

L1-E08 — Testing & Deployment

## Goal

Complete deterministic Layer 1 acceptance and prepare a reproducible, resource-conscious production deployment, backup, recovery, and rollback package without mutating the live server or using real credentials.

## Scope

- critical-path acceptance covering authentication, folders, a representative PDF, browse/download, rename/move, recycle, restore, owner isolation, restart, and metadata/object-reference persistence
- representative PDF/image/text/binary metadata and authorization checks without sending bytes to a real provider
- consistent SQLite online backup, read-only verification, restore rehearsal, migration upgrade, and rollback procedures
- production build/release layout, environment template, Nginx HTTPS/static/API configuration, and hardened single-process systemd unit
- OSS private-bucket, RAM, CORS, versioning, timeout, and browser-direct upload deployment checklist
- local production-artifact validation, dependency/security checks, memory benchmark, restart/redeployment simulation, and final Layer 1 exit review

## Non-goals

- real Alibaba Cloud credentials, account/RAM/bucket/DNS/CORS/versioning changes, TLS issuance, billable resources, or live OSS calls
- SSH/server access, package installation, service enablement, firewall mutation, production database/object changes, or deployment cutover without a separate approval gate
- Docker, Redis, queue services, multiple application instances, automatic orphan cleanup, or Layer 2/3 work
- claiming live-cloud or 512 MB Ubuntu measurements from deterministic local tests

## Acceptance Criteria

- [x] a deterministic critical-path acceptance test satisfies all ten Layer 1 success steps and repeats across a persistence restart
- [x] representative PDF, image, text, and binary cases preserve exact size/type/checksum and safe preview/download behavior
- [x] SQLite backup uses a consistent online mechanism, refuses overwrite, verifies integrity/FKs/migrations, and survives an isolated restore rehearsal
- [x] deployment artifacts define one loopback-bound Node process, Nginx HTTPS/static/API routing, restrictive permissions, graceful restart, and explicit resource limits
- [x] production configuration and OSS checklist keep secrets server-side and require private bucket, exact CORS origin, no-overwrite-compatible versioning, least-privilege RAM, and short-lived authorization
- [x] release, migration, backup, restore, rollback, maintenance, logging, readiness, and incident procedures are documented with verification and abort points
- [x] local restart/redeployment and compiled production maintenance/backup entry points are exercised without real cloud access
- [x] tests, type-check, production builds, both dependency audits, integrity checks, benchmark, secret scan, artifact review, and diff check pass
- [x] project status records distinguish locally completed Layer 1 acceptance from approval-gated live deployment/credential operations
