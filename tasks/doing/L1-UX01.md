## Goal

Fix the three genuine product usability defects found during the Owner's real-browser Product Verification after the passing live E2E: (1) English-only interface → complete zh-CN/en UI switching; (2) uploads feel slow and phases/speed are unclear → explicit upload phases, real network speed + ETA, stall-safe timeouts, and a bounded concurrency queue; (3) Preview triggers a browser download and Unicode filenames garble → correct browser-native inline preview via a dedicated OSS custom browser domain architecture plus Unicode-safe Content-Disposition. Implementation + testing + infrastructure preparation + deployment plan ONLY.

## Scope

- typed internal localization layer (zh-CN, en; localStorage key `academiccloud.language`; `navigator.language` zh-prefix detection; immediate switching; `document.documentElement.lang`), compact `中文 | EN` switch on the login page and authenticated top bar, localized UI/aria/errors/dates/numbers
- upload UX: distinct phases (排队等待/计算校验值/准备安全上传/上传/验证云端文件/完成/需要处理 + English), real XHR-progress-based bytes/speed/ETA (throttled), inactivity stall timeout (120 s default) replacing the fixed 15-minute total timeout, bounded concurrency-2 queue (completion/failure/cancellation release a slot), MD5 integrity contract unchanged
- preview: dedicated OSS browser GET endpoint (`OSS_BROWSER_ENDPOINT`, cname semantics, optional; when absent inline authorization fails safely with `preview_unavailable` and a localized message), separate native service endpoint for HEAD/Delete/upload, inline disposition without filename parameters, attachment disposition with RFC 5987 Unicode `filename*` + ASCII fallback
